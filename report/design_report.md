# 基于 PYNQ-Z2 的 OV5640 自适应 ISP

## —— 感知—决策—执行闭环的 FPGA 图像前端

> 参赛组别：初级组  
> 器件：PYNQ-Z2（XC7Z020）  
> 工具：Vivado / Vitis HLS 2024.2  
> 说明：本文中的数字均来自 `docs/results/` 与板上实测日志；
> 标注“待补”的位置由队伍按最终演示环境填写。

## 摘要

固定曝光的摄像头在窗边逆光场景中容易出现高光饱和、暗部丢细节；
摄像头自带的 AEC/AGC 只能调整全局亮度，难以同时保住高光和暗部。
本文在 PYNQ-Z2 + OV5640 上实现了一条“感知—决策—执行”闭环的
自适应 ISP：PL 侧逐像素统计亮度、亮度平方、梯度和四象限亮度；
PS 侧用 3-8-3 Q8.8 MLP 判断暗光/逆光/常规，并用四象限空间规则
区分“整体偏亮”和“中间暗、四周亮”；执行侧按模式与连续 PARAM
做增益、逆光补偿和锐化，所有参数在帧边界生效，切换不撕裂。

系统在 1280×720@30 下实测 29.7 fps，stage13 时序 WNS +0.120 ns，
LUT/FF/BRAM/DSP 分别约 29.82%/19.49%/22.50%/26.36%。按采集轮次留出的 3 折评估中，
3 特征 MLP 的 macro-F1 为 1.000，固定亮度阈值为 0.942；
同亮度 hard pair 中，两个场景 `f_luma` 仅差 1，MLP 都判 0，
四象限把亮窗场景改判为 mode 1。本作品不是“只看全局亮度切三档”，
而是把空间布局作为可解释的第二判据，并给出了可复现的证据链。

**关键词**：PYNQ；OV5640；自适应 ISP；AXI4-Stream；HLS；定点 MLP；
四象限统计；软硬件协同

## 1. 选题背景与创新点

### 1.1 问题

边缘视觉设备（仓库监控、机器人、低光摄像头）经常遇到三类场景：

* **暗光**：整体亮度低，需要提亮，但不能把噪声放大到不可用；
* **逆光**：窗/灯进入画面，主体暗、背景亮；全局提亮会把高光打到 255；
* **常规**：亮度适中，适合轻增强/锐化。

固定曝光无法同时覆盖三类；摄像头自带 AEC/AGC 只能调全局亮度，
在“窗边逆光”下要么主体仍暗，要么高光过曝。

### 1.2 前人做法与不足

| 做法 | 不足 |
|---|---|
| 固定 3 档 LUT / 固定 gamma | 不随场景变化，暗光和逆光只能二选一 |
| 纯全局统计 + 阈值 | 只能按亮度分级，逆光和“整体偏亮”分不清 |
| 纯 PS 软件逐像素处理 | 921600 像素/帧，CPU 难做到 720p30 实时 |
| 大模型/CNN | 资源与功耗高，边缘 Zynq-7000 上不现实 |

### 1.3 本作品的创新点

1. **PL 逐像素统计 + 四象限空间信息**：不仅看全局亮度，还看“亮区在哪”；
2. **MLP + 空间规则的混合决策**：MLP 判 0/1/2，四象限 `u>=0.55`
   时改判逆光补偿，`u<=0.30` 时信任 MLP，中间保持；
3. **连续 PARAM**：不是三档写死强度，而是按亮度/对比度/细节实时算；
4. **帧边界切换**：`mode_active` 在 `tuser` 重采样，切换不撕裂；
5. **可复现的证据链**：hard pair、3 折留一、实时 12 秒日志、分屏自洽。

### 1.4 应用价值

本作品面向“窗边逆光/暗角/正常光”频繁切换的边缘视觉前端。
它不依赖云端大算力，适合 Zynq-7000 级别的设备；
四象限规则放在 PS 侧，改阈值不用重综合，便于现场标定。

## 2. 系统总体设计

### 2.1 数据流

```text
OV5640 -> v_vid_in_axi4s -> v_demosaic
       -> axis_video_proc (统计 + 四象限 + MLP 握手 + 可重构处理)
       -> axi_vdma_0 (S2MM) -> DDR
       -> axi_vdma_0 (MM2S) -> axi_vdma_1 (S2MM) -> DDR
       -> axi_vdma_1 (MM2S) -> v_axi4s_vid_out
       -> rgb2dvi -> HDMI
```

自定义 IP 插在 `v_demosaic_0/m_axis_video` 和
`axi_vdma_0/S_AXIS_S2MM` 之间。原因是：

* 这里是整条链路唯一的 24-bit RGB + `tuser/tlast` 原始像素流；
* 处理结果同时进入 Jupyter 抓帧和 HDMI；
* `v_demosaic` 自带帧缓存，插一个纯流水线 IP 不会破坏采集；
* 不需要重建已经验证过的 VDMA 通路。

### 2.2 三条线

| 线 | 内容 |
|---|---|
| 像素线 | 24-bit RGB，`tuser`=帧首，`tlast`=行尾，100 MHz |
| 统计线 | 亮度 → 梯度 → 平方 → 累加，4 级流水，帧边界锁存 |
| 决策线 | MLP（HLS）→ 置信度门限 → 四象限 → 防抖 → 帧边界写寄存器 |

### 2.3 帧边界切换

视频流里没有独立 vsync，只有 `tuser`（帧首）和 `tlast`（行尾）。
IP 在 `tuser` 上重采样 `MODE_SEL`/`PARAM`，因此 CPU 在任何时刻写寄存器，
真正生效都在下一帧开始，避免半帧换模式造成的撕裂。

## 3. 软硬件划分与接口设计

### 3.1 划分依据

| 放哪 | 做什么 | 为什么 |
|---|---|---|
| PL | 逐像素亮度/梯度/平方累加、四象限、像素处理 | 921600 像素/帧，PS 逐像素太慢 |
| PL/HLS | 3-8-3 Q8.8 MLP | 每帧一次，约 70 ns，确定性强 |
| PS | 置信度门限、四象限规则、防抖/最小驻留、PARAM 计算 | 规则要调，改 Python 不用重综合 |
| AXI4-Stream | 视频流 | 与 demosaic/VDMA 原生接口 |
| AXI-Lite | 寄存器 | 0x00~0x3C，见 `docs/01_register_map.md` |

**关键取舍**：统计用硬件、决策用软件。四象限规则是零额外 LUT/DSP 的，
这是“软硬件协同”，不是“什么都塞进 PL”。

### 3.2 寄存器映射

| 偏移 | 名称 | 读写 | 含义 |
|---|---|---|---|
| 0x00 | `MLP_OUTPUT` | R | 分类结果 0/1/2 |
| 0x04 | `MODE_SEL` | R/W | 处理模式 |
| 0x08 | `STATUS` | R | 推理完成/帧边界/统计就绪 |
| 0x0C | `VERSION` | R | 版本 |
| 0x10~0x28 | 统计寄存器 | R | `sumY / sumY² / sumGrad / pixel_cnt` |
| 0x34 | `PARAM` | R/W | 连续处理强度 0~255 |
| 0x38/0x3C | 四象限 | R | TL/TR/BL/BR 的 `sumY>>16` |

### 3.3 时序收敛

阶段 3 最初把“三个乘法求亮度 → 平方 → 48 位累加”压在一个 100 MHz 周期里，
实测 WNS -5.4 ns。最终把统计链路拆成四级：

```text
px1_* -> 亮度 -> 梯度 -> 平方 -> 累加
```

并把统计源改成本模块自己的寄存器 `px1_*`，把 `v_demosaic` 输出 mux
和长走线从关键路径上摘掉。stage7 报告 WNS +0.134 ns，
stage13 文档记录 WNS +0.120 ns，失败端点 0。

## 4. 关键实现

### 4.1 逐像素统计

```text
Y      = (77*R + 150*G + 29*B) >> 8
f_luma = SUM(Y)      >> 20
f_luma2= SUM(Y²)     >> 28
f_grad = SUM(|ΔY|)   >> 16
```

三个移位都在 `lib/ai_video_regs.py` 的 `MLP_FEAT_SHIFT` 里定义，
HDL/HLS/Python 三处必须一致。早期 `f_grad` 用 `>>20` 时整列恒等于 2，
后来改成 `>>16` 才有分辨率。

### 4.2 轻量 MLP

3-8-3，Q8.8 定点；HLS `II=1`、`Depth=7`，100 MHz 下约 70 ns。
训练时把归一化折进第一层，硬件不需要除法；量化前做 int32 溢出检查。

### 4.3 四象限空间决策

四象限统计 `(TL,TR,BL,BR)` 在 0x38/0x3C，单位 `sumY>>16`。

```text
u = (max(q) - min(q)) / mean(q)
```

实测：

| 场景 | f_luma | u |
|---|---|---|
| 均匀暗场 | 9.0 | 0.101 |
| 暗场+亮窗 | 8.0 | 2.168 |
| 均匀正常光 | 99.8 | 0.267 |
| 正常+逆光 | 116.0 | 1.151 |

规则：

* `u >= 0.55`：空间明显不均 → mode 1（逆光补偿）；
* `u <= 0.30`：照明均匀 → 信任 MLP 的 0/2；
* `0.30 < u < 0.55`：保持当前模式（迟滞）。

### 4.4 连续 PARAM

| 模式 | PARAM 含义 | 算法 |
|---|---|---|
| 0 增益 | 128=×1.0，255≈×1.99 | 按实测亮度反推，越暗越大，到目标回 1.0 |
| 1 逆光补偿 | 128=±32，255=±63 | 按对比度反推，反差越大补得越狠 |
| 2 锐化 | 0=直通，128=\|Δ\|/2，255≈\|Δ\| | 按细节量反推，细节少时更强 |

参数在帧边界与 `MODE_SEL` 同步锁存，调参数不撕裂。

### 4.5 置信度门限与防抖

特征离目标类中心太远、或判决类不是最近类时，拒绝这次 MLP 判决，
保持当前模式；再叠 `debounce` 和 `min_hold`，避免边界来回跳。

### 4.6 HDMI 分屏

stage13 用 640×24 bit 行缓冲，把“处理后的同一段源列”放到屏幕右半，
左半是原始列；1:1 不缩放。同帧自洽 RMS 0.09（判据 <3），
列剖面中位差 1~2，错配项 176（判据 >100）。

## 5. 优化过程与性能/资源对比

### 5.1 固定强度 vs 连续自适应

来源：`docs/results/step5_compare.md`。

| 场景 | 固定 mode0（×1.5） | 自适应 | 收益 |
|---|---|---|---|
| 暗光 | 均值 12.7，饱和 0.0% | PARAM=255（×1.99），均值 16.4 | 提亮 **+29%**，不过曝 |
| 常规 | 均值 163.4，**饱和 29.4%** | PARAM=128（×1.0），均值 117.4 | 饱和 **29.4% → 0.4%** |

### 5.2 MLP vs 固定亮度阈值

来源：`docs/results/eval_rounds.md`。3 折 leave-one-round-out：

| 方法 | macro-F1 |
|---|---|
| 3 特征 MLP | **1.000 ± 0.000** |
| 固定亮度两级阈值 | **0.942 ± 0.041** |

### 5.3 空间决策 hard pair

来源：`docs/results/hard_pairs.md`。

| pair | 场景 A | 场景 B | Δf_luma | Δu | MLP A/B | 空间 A/B |
|---|---|---|---|---|---|---|
| 0 | 均匀暗场 | 暗场+亮窗 | **1.0** | **2.067** | 0/0 | **0/1** |
| 1 | 均匀正常光 | 正常+逆光 | 16.2 | 0.885 | 2/1 | 2/1 |

**主结论只引用 pair 0**：同亮度、MLP 同判、空间改判。
pair 1 的亮度差 16.2，只作辅助证据。

逐帧指标（`tools/eval_holdout.py`，240 帧）：
纯 MLP acc **0.750** / macro-F1 0.778；MLP+四象限 acc **1.000** / macro-F1 1.000；
空间覆盖 60 次、保持 0 次；逆光类 recall 从 **0.500 → 1.000**。

### 5.4 实时闭环

来源：`docs/results/live_scheduler.md`。四场景各 12 秒：

| scene | f_luma | u | MLP raw | 最终 mode | PARAM |
|---|---|---|---|---|---|
| 0 均匀暗场 | 7.84 | 0.064 | 0 | 0 | 255 |
| 1 暗场+亮窗 | 9.78 | 2.432 | 0 | **1** | 166 |
| 2 均匀正常光 | 105.62 | 0.263 | 2:570/1:6 | 2 | 190 |
| 3 正常+逆光 | 80.29 | 2.239 | 1 | 1 | 242 |

最终模式 **0/1/2/1**，29.7 fps，无场景内振荡。

> 版本说明：本文所有板上数据均在 **stage13 rev02**
> （`VERSION=0x0001020D`）上采集。早期一次 preflight 曾读到
> stage12 的旧 overlay 文件（`0x0001030C`），后续已统一替换为 stage13；
> 两版都包含 `PARAM` 和四象限寄存器，差别只在 stage13 多了 HDMI 分屏。

### 5.5 时序与资源

来源：`docs/results/timing.md`。

* setup：WNS **+0.120 ns**、TNS 0、失败端点 0；
* hold：WHS **+0.016 ns**、THS 0、失败端点 0；
* LUT 29.82% / FF 19.49% / BRAM 22.50% / DSP 26.36%；
* DRC：0 Error / 0 Critical Warning；methodology：4 类 Critical Warning，其中 152 项来自 `vid_pclk` 无顶层时钟覆盖；
* 29.61 fps（720p30）。

因此，本文的正确结论是“用户已指定约束内时序全部通过，板级功能和长时运行已验证”；
不能写成“整个设计零 Critical Warning”。摄像头输入时钟覆盖缺口已作为限制保留。

### 5.6 讨论

* MLP 相对亮度阈值的优势主要来自“轮次间光照漂移”下的边界稳定性；
* 四象限的价值不在总体准确率（已经饱和），而在“同亮度、不同空间”的
  hard case；pair 0 是直接证据；
* 连续 PARAM 把常规场景的饱和率从 29.4% 降到 0.4%，这是可量化的收益；
* 四象限统计在 PL 侧使用累加器，空间判断本身在 PS 侧完成；最终整体 DSP 占用为 58/220（26.36%）。

### 6.1 真实场景 holdout

120 帧（3 场景 × 40），用部署权重、不重训：

| 场景 | f_luma | u | MLP | MLP+四象限 |
|---|---|---|---|---|
| 真实暗场（重采） | 4.0 | 0.124 | 0 | 0 |
| 真实窗边逆光 | 50.2 | 2.497 | 1 | 1 |
| 真实室内正常光 | 107.7 | 0.385 | 2 | 2 |

纯 MLP **120/120 = 1.000**；MLP+四象限 **120/120 = 1.000**。
空间覆盖 **0 次**、保持 **40 次**。

scene0 重采后四象限是 `(15,17,16,17)`，`u=0.124 < 0.30`，
空间规则信任 MLP，两者都判 0；
scene2 的 `u=0.385` 落在 0.30~0.55 的迟滞带，40 帧“保持”，
mode 仍为 2，没有误切。

结论：模型在 3 个真实场景上泛化良好；空间规则在均匀暗场/正常光上
不会乱覆盖，它的价值在 hard pair（同亮度、不同空间布局）。
早期 scene0 是“暗场+右侧亮区”（u=0.953），已重采，报告不再使用旧数据。

## 10. 限制与后续工作

* 三分类（暗光/逆光/常规），不是通用场景理解；
* 当前数据 540 帧、3 轮盒子标定，真实房间泛化仍需补测；
* 四象限只有 4 块，不能定位小面积高光；
* 720p30，不是 60 fps；
* pair 1 的 `|Δf_luma|=16.2`，只作辅助证据；
* 3-8-3 MLP 容量小，但胜在可解释、资源低；
* 后续：5 特征 MLP、直方图/percentile、更多 HLS 模式、真实场景数据。

## 11. 结论

本作品在 PYNQ-Z2 上完成了一条可复现、可演示的“感知—决策—执行”
自适应 ISP。它的核心不是“更大的模型”，而是：

1. 用 PL 做逐像素统计，用 PS 做可调规则，软硬件分工合理；
2. 用四象限空间信息补上纯亮度分类器的盲区；
3. 用连续 PARAM 和帧边界切换，把“自适应”做成可测量的画质收益；
4. 用 hard pair、留一评估、实时日志和分屏自洽，形成完整证据链。

同亮度 hard pair 中，两个场景 `f_luma` 仅差 1，MLP 都判 0，
四象限把亮窗场景改判为 mode 1；这是“不是纯亮度分类器”的直接证据。
