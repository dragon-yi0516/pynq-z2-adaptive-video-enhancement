# golden_reference_ci

## 适用场景

任何“Python/浮点参考模型 → HLS/RTL/板上输出”的定点实现：

* 想确认 HLS CSim 与 Python 定点参考逐条一致；
* 想确认板上推理结果与黄金参考只差“已知的 1 帧延迟”；
* 想把比对结果直接生成一张可进报告的差异表。

## 使用方法

1. 参考模型和实现各导出一份 CSV，至少包含：

```csv
case,expected
0,0
1,1
2,2
```

```csv
case,actual
0,0
1,1
2,1
```

2. 比对：

```bash
python3 compare_csv.py --expected example/expected.csv \
  --actual example/actual.csv --key case
```

3. 在 CI 里用退出码判断：0 = 通过，1 = 有差异。

## 失效条件

* 两份 CSV 的 key 集合不一致（脚本会单独报 missing/extra）；
* 输出是浮点数（请先在参考模型里量化成整数再比）；
* 板上结果是“特征 N 对应判决 N+1”这种已知延迟（先把两份 CSV 对齐一帧再比，
  不要直接放宽阈值）。

## 已验证效果

本项目：

* 124 条 MLP 测试向量，Python Q8.8 定点参考 vs HLS CSim：`fail=0`；
* 板上 17 帧 monitor 复算：14 帧完全一致，3 帧差异可由“推理比特征晚 1 帧”
  解释；把对齐关系写进报告，而不是硬说 17/17。

## 提炼来源

本项目早期踩过两次：

1. `f_grad` 的移位写成 `>>20`，整列恒等于 2，训练/推理都“能跑”但特征废了；
2. 训练权重更新后忘了重出 bitstream，板上一直跑旧模型。

把“参考 → 向量 → CSim → 板上”每一步都落成 CSV 和退出码，
比人眼看日志可靠。

## 边界

这不是形式等价证明；它只验证你导出的那批测试向量。
测试向量要覆盖边界值（0、最大值、量化饱和点），否则 124 条全过也可能漏掉角落。
