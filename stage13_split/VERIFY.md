# 阶段 13 验收清单：HDMI 分屏输出

对应 `docs/06_split_screen_options.md` 的方案 B。在阶段 12 基础上**只加了输出分屏**，
处理逻辑、统计、连续参数、MLP 握手全部不变。

## 这一版改了什么

| 项目 | 阶段 12（v2.0 / 0x0001_030C） | 阶段 13（v2.2 / 0x0001_020D） |
|------|-------------------------------|-------------------------------|
| HDMI 画面 | 整屏 = 处理后的画面 | 开关打开时：**左半 = 原始、右半 = 处理后的同一区域** |
| 新增硬件 | — | 640×24 bit 行缓冲（约 1.9 KB BRAM）+ 输出列选择 |
| 新增开关 | — | `MODE_SEL` 的 **bit7**（默认 0 = 关，行为与阶段 12 完全一致） |
| 其它 | — | 不动 |

### 为什么是「左半原始 / 右半处理后的同一区域」

输入 1280 宽、输出也 1280 宽。每一行这样安排：

    屏幕左半 640 列  <-  原始画面的第 0~639 列（未处理）
    屏幕右半 640 列  <-  处理后的第 0~639 列（同一区域！）

两边内容**完全一致**，只有「处理 / 未处理」的区别，对比最直观；
而且 640×720 放进 640×720 的格子，**1:1 不缩放**，不需要 scaler。

代价：视野只剩画面的左半边（固定的那 640 源列），演示时要把主体放进这半幅里。

> 修订记录：rev01（`0x0001_010D`）列计数在行间消隐期也自增，每行错位累积，表现为
> 黑带 + 左右内容错乱；rev02（`0x0001_020D`）改成只在有效像素拍计数。

## 3. 左右对比（关键验收）

1. 打开分屏，画面停在**有明暗纹理**的场景上（白墙看不出效果）；
2. 切 `MODE_SEL=0` 且 `PARAM=255`（增益 ×1.99）；
3. 看显示器：

- [x] **左半边明显比右半边暗**（左边原始、右边被提亮）
- [x] 左右两半是**同一个画面区域**（不是画面的左右两半）
- [ ] 切换模式时**只有右半边变**，左半边始终是原始画面
- [ ] 用 `MODE_SEL=2`（锐化）时，右半边更「脆」、左半边更「糊」

> 怎么确认「左右是同一区域」：拿一张写着字的纸，只让**左边那半个字**入画，

## 5. 出问题时的回退

| 现象 | 处理 |
|------|------|
| 时序不收敛 | 行缓冲读改同步读；或退回阶段 12 的 bit |
| 右半边黑 / 花屏 | 行缓冲读地址不对，把日志发我 |
| 左右内容不一致 | 列计数没对齐，把现象描述发我 |
| 分屏开关无效 | 确认 `VERSION` 是 `0x0001020D`（不是 0x0001030C） |

## 6. 实测记录（2026-10-08，板上）

同一次采集的三个帧，`PARAM` 分别为 128 / 255：

| 量 | 数值 |
|---|---|
| `A`（全屏原始）均值 | 112.3 |
| `B`（全屏处理）均值 | 184.2 |
| `S`（分屏）均值 | 150.1（正好在两者之间） |

RMS 配对（`frame_to_rgb()` 做了一次水平镜像，所以**数组左半 = 显示器右半**）：

| 配对 | RMS | 结论 |
|---|---|---|
| `S[:, :640]` ↔ `B[:, 640:]`（处理后，同一区域） | 约 4 | 匹配 |
| `S[:, 640:]` ↔ `A[:, 640:]`（原始，同一区域） | 3.90 | 匹配 |
| `S[:, :640]` ↔ `B[:, :640]`（另一半区域） | 82.82 | 不匹配 |
| `S[:, 640:]` ↔ `B[:, 640:]`（同半但是处理后） | 83.01 | 不匹配 |

结论：分屏左右两边是**同一个画面区域**的「原始」与「处理后」，设计达成。
