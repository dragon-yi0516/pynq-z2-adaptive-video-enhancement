## 1. 开场（30 秒）

跑 `09_demo.ipynb` 第 1 幕，念出：

* overlay 文件路径
* `VERSION = 0x0001030C` → 家族 1、修订 03、**硬件阶段 12**（MLP + 可重构阵列 + 连续参数）
  （编码是 `0x0001_RRSS`：RR=修订号、SS=阶段号。**别念成 0x00010012**）
* `PARAM` 寄存器（0x34）会随场景连续变化 —— "连续自适应"的直接证据；
  第 3 幕顺口提一句"模式决定用哪种处理，强度由 PARAM 按实测特征实时算"
* IP 清单里有 `axis_video_proc_0`（MLP 引擎是它的子 IP，不会单独出现在清单里）

## 2. 感知（1 分钟）

跑第 2 幕，然后用**盒子里的三档**依次造场景（不要再用手遮镜头 —— 那是旧流程，
而且遮出来的画面没有纹理，第三类的"暗光"会退化成"全黑"）：

1. 主光源关到最暗 → `MLP=0`（暗光）
2. 后壁光板开 + 主光源关 + 黑卡纸剪影 → `MLP=1`（逆光）
3. 主光源中亮 + 对着白纸/网格卡 → `MLP=2`（常规/细节）

强调：**这三个数完全是 FPGA 里算出来的**，PS 只读寄存器。
每个档位**停 2 秒**再换下一个 —— 免得屏幕和你念的话对不上。

## 3. 决策 + 执行（2 分钟）

跑第 3 幕（后台调度），然后重复上面的三个场景。此时画面会**自动**变亮 / 压逆光 / 变锐。

强调三点：

* 连续 3 次判定一致才切换 → 防抖；
* **置信度门限**：特征离各类中心太远（归一化 > 12σ）或判决类不是最近类时，直接判成"不可信"、
  保持当前模式 —— 日志里 `门限拒绝：…` 那几行就是证据；
* 切换发生在**帧边界**（硬件 `tuser` 重采样）→ 不撕裂。

注意：第 3 幕**不要**先释放 VDMA 通道 —— 那样 HDMI 会黑屏。脚本用 `--base` 模式，
只戳自有 IP 的寄存器，采集 + 显示通路保持不动，所以屏幕上能直接看到画面随场景自动切换。

## 8. 常见提问准备

| 可能被问 | 回答要点 |
|---------|---------|
| 为什么插在 demosaic 后面而不是直接接 HDMI？ | 复用已经验证过的 VDMA 通路，风险最低；处理结果同时进 Jupyter 和 HDMI |
| 为什么特征不是物理量？ | FPGA 零成本只能给移位/加法；物理量由 PS 换算供人工检查，MLP 输入是三个统计量 |
| 为什么用 Q8.8 而不是浮点？ | 省 DSP、时序好，且定点/浮点一致率实测 100% |
| 会不会因为换模式导致判断自激？ | 不会：特征取自**处理前**像素 |
| **为什么要锁曝光？** | AEC/AGC 会自动改曝光/增益，噪声一变 `f_grad` 就偏十几点，三类中心和训练分布对不上（实测逆光档会一次都判不出来）。采集、演示、对比必须同一档 |
| **门限是干什么的？** | 训练数据只覆盖三个档位附近，中间地带的判决是外推、会乱跳。门限要求"归一化距离 ≤12σ 且判决类是最近类"，不满足就保持当前模式 —— 日志里能看到它拒了多少次 |
| 端到端延迟多少？ | 约 3 帧 ≈ **100 ms @30fps**（统计 1 帧 + 切换 ≤1 帧 + 显示 1 帧）。注意 720p30 一帧就是 33.3 ms，别答成 50 ms |
| 帧率多少？ | **29.6 fps**（720p30；60 秒长跑里 27.3~29.8，属正常波动） |
| 怎么保证笔记本和板子一致？ | Python 参考实现生成测试向量，HLS csim 逐条比对（`TV_N=124 fail=0`）；板上再用逐帧比对复核 |

## 8.5 现场出故障怎么办（演示前扫一眼）

| 症状 | 原因 | 处理 |
|------|------|------|
| `CompletedProcess(..., returncode=-11)` | 两个进程抢同一块 PL（内核里已经加载过 overlay，又用 `subprocess` 去跑采集脚本） | 改成**同一个内核**里调用（`s5.main([...])`）；不要用 `subprocess` |
| `RuntimeError: Allocate failed: 4294967295` | XRT 分不出 DMA 缓冲了 —— **最常见的原因是一台机器上开着好几个 Jupyter 内核**，每个都占着自己那份 DMA 缓冲；其次是被 SIGKILL/『停止』打断过的采集进程 | ① **关掉用不到的 notebook 内核**（Shut Down Kernel）；② 当前 notebook `Restart Kernel` + 从上往下重跑；③ `bash tools/pl_cleanup.sh` 看证据；④ 还不行才 `sudo reboot`。**别指望 `ol.free()`/`s5.release()` 救场**（实测 free 完再分配更容易失败） |
| 按了『停止』之后读数/画面不对劲 | 通道被半途打断，PL 状态不干净 | `Kernel → Restart Kernel` 再跑；还不对就重启板子 |
| HDMI 一直黑 | 采集 notebook 只起了 S2MM，没起显示通路 | 跑一次 `vp.start_hdmi_passthrough(vdma0, vdma1, mode)` |
| **遮住镜头却判不出暗光档**（`MLP_OUTPUT` 总在 1/2 之间跳） | 演示 notebook 用了自动曝光：AEC 会把画面顶回正常亮度 —— 实测遮住画面后 `f_luma` 还有 41（暗光类中心是 10） | `09_demo` / `10_split_compare` 的初始化格现在锁 `exposure.WORKPOINT`（736 行 / 0x20）。确认那格打印了 `[exposure] 已切手动：曝光 = 736 行…`；没打印就是灯/曝光没锁上 |

一句话原则：**采集类脚本要独占 PL，别在它跑的时候按『停止』；真要中断就 Restart Kernel。**
