**HDL 的三处改动**（数据通路结构没动）：

1. **新增 `PARAM` 寄存器（0x34）** —— 三种处理的强度从"写死"改成"连续可调"：

   | 模式 | 阶段 7（固定） | 阶段 12（连续） | PARAM 含义 |
   |------|--------------|----------------|-----------|
   | 0 增益 | `c × 1.5` | `c × (PARAM/128)` | 128=×1.0，192=×1.5，255=×1.99 |
   | 1 对比拉伸 | 只在 <96/>160 起作用 | `c ± \|c-128\|×PARAM/512` | 最大 ±32（128）～ ±63（255） |
   | 2 锐化 | `c ± \|c-p\|/2` | `c ± \|c-p\|×PARAM/256` | 0=直通，128=\|Δ\|/2，255≈\|Δ\| |

2. **新增四象限亮度统计（0x38 / 0x3C）** —— 只要全局 sumY 的话，
   "上亮下暗的逆光"和"整体偏亮"可能差不多；切成 4 块分别求和后，
   上位机算一下块间比值就能分开。**这是答辩时回应"这是不是纯亮度分类器"的直接证据。**

3. **VERSION 升到 `0x0001_010C`**（家族 1 / 修订 01 / 阶段 12），板上读寄存器就能确认版本。

### 新增：软件

| 文件 | 作用 |
|------|------|
| `lib/adaptive.py` | **连续自适应策略**：把实时特征换算成 (mode, param)，并附带"为什么这么算"的说明 |
| `lib/ai_video_regs.py` | 加了 `PARAM` / `QUAD_TL_TR` / `QUAD_BL_BR` 常量，`set_param()` / `quads()` / `spatial_unevenness()` / `has_param()` |
| `stage08_auto_schedule/auto_schedule.py` | 加了 `--adaptive` 和 `--param` 两个开关 |

`lib/adaptive.py` 里三个参数映射是**针对阶段 7 实测到的毛病**设计的：

* `gain_param()`：阶段 7 固定 ×1.5，在正常亮度下把 **26.7% 的像素打到饱和**（实测）。
  现在按实测亮度反推增益（越暗越大、到目标就回 1.0），**不会过曝**。
* `stretch_param()`：阶段 7 的对比拉伸对 96~160 的像素**完全不变**，普通画面里看不出效果。
  现在按对比度反推强度（对比度越低拉得越狠）。
* `sharpen_param()`：阶段 7 固定 |Δ|/2（水平差分只 +26%）。
  现在细节少时锐化更强（最多接近全强度），细节多时收敛以免放大噪声。

### 步骤 2 的实测结果与两个修订（2026-10-08）

第一次验证（修订 02）结果：**连续参数确实生效**，但发现两个问题，都已在修订 03 修掉。

| 检查 | 结果 |
|------|------|
| mode 0 增益扫 PARAM | 均值 59.4→73.3→88.9→102.8→117.4，**单调升**；PARAM=192 时 59.4×1.5=89.1 与实测 88.9 完全对上 |
| mode 0 饱和率 | **全程 0.0%**（阶段 7 固定 ×1.5 时是 26.7%）→ "不过曝"这个目标达成 |
| mode 2 锐化 | 均值不变、**水平差分 4.77→6.13 单调升** |
| mode 1 | 均值升、std 降（压对比），方向与预期相反 → 见下面问题 2 |
| `regs.param()` / `regs.quads()` | **恒为 0** → 见下面问题 1 |

**问题 1（HDL bug，已修）**：读通道的地址译码写错了。
`reg_read` 的 `case` 比的是**字节地址**（6'h00/6'h04/6'h0C…），
而修订 02 里新加的 0x34/0x38/0x3C 写成了**字索引** 6'h0D/0E/0F → 永远命中 `default`。
写通道用的是 `aw_addr[5:2]`（正好是字索引）所以是对的，**参数确实写进去了**，
只是读不回来。修订 03 改成 6'h34/38/3C。

顺便给 `reg_param` 加了上电初值 192：它原来只在 `!aresetn` 分支里赋值，
如果复位没有重新拉低，FF 会保持上电值 0，而 PARAM=0 会让 mode 0 增益变成
×0（整屏黑）。用初值把上电值定死。

**问题 2（软件逻辑，已修）**：`adaptive.stretch_param()` 的方向反了。
原来写成"对比度越低补偿越强"，但逆光补偿是**反差越大补得越狠**才合理。
修订 03 反过来：对比度 20→PARAM=128（轻微）、80→PARAM=255（最强）。
实测自测：对比度 13→PARAM=128、26→140、75→244。

**问题 3（notebook 笔误，已修）**：`adaptive.decide()` 返回 3 个值，
notebook 里写成解包 2 个，检查 3 报 `too many values to unpack`。已改成 `_, p, why = ...`。

**如果时序不收敛**：把 `logs/stage12_*.log` 发我。可能的原因和新加的两处逻辑有关：
三种模式的参数化乘法（`c * param`）会占用 DSP 并在像素路径上加一级乘法；
四象限统计加了一组加法器。都是**可以优化掉的**（比如把 PARAM 换成移位档位），
但先看报告里的违例路径落在哪儿再说。

**如果报语法错误**：先跑 `python3 tools/check_verilog.py`（我这边已经过了，
但如果 Vivado 报具体行号，发我，通常一行就能修）。

### 步骤 5：量化对比实验（30 分钟，答辩硬货）

同一场景下对比"固定模式"和"连续自适应"：

```python
def shoot(mode, param=None, warm=5):
    regs.set_mode(mode)
    if param is not None:
        regs.set_param(param)
    for _ in range(warm):
        regs.wait_new_frame()
    raw = vp.capture_frame(vdma0)
    return vp.frame_to_rgb(raw).astype(np.float32)

def quality(a):
    # 用「对比度」和「清晰度」两个指标量化画质
    return float(a.std()), float(np.abs(np.diff(a, axis=1)).mean())

for scene in ("暗光", "逆光", "常规"):
    print("---- 场景：%s ----" % scene)
    # 固定（阶段 7 行为）
    m = {"暗光": 0, "逆光": 1, "常规": 2}[scene]
    a = shoot(m, 192)
    print("  固定     对比度=%.1f 清晰度=%.2f 饱和=%.1f%%"
          % (quality(a) + (100.0 * (a >= 255).mean(),)))
    # 自适应
    f = regs.mlp_features()
    p, why = adaptive.decide(f, m)
    b = shoot(m, p)
    print("  自适应   PARAM=%d (%s) 对比度=%.1f 清晰度=%.2f 饱和=%.1f%%"
          % ((p, why) + quality(b) + (100.0 * (b >= 255).mean(),)))
```

**预期结论**（这是你要在报告里写的"自适应带来的收益"）：
固定模式在暗光下提亮不足、在正常亮度下 26.7% 过曝；
自适应把增益按亮度反推，**饱和率降下来、有效对比度提上去**。

## 四、答辩叙事怎么改

改之前："FPGA 上做可重构处理阵列 + MLP 自适应增强" —— 3 个模式 + 3-8-3 的 MLP，撑不满。

改之后的三个层次（每一层都有硬数据）：

1. **感知**：硬件逐像素统计 3 个全局特征 + 4 个象限（**空间**信息），
   3 级流水，源头接本模块寄存器（WNS +0.134 ns 的由来）；
2. **决策**：HLS 上跑 Q8.8 定点 MLP（片上延迟 < 1 µs），
   csim 与 Python 定点参考逐条比对；
3. **执行**：**连续参数自适应** —— mode 决定"用哪种处理"，PARAM 按实时特征连续算，
   而且参数在**帧边界**锁存（不撕裂）。暗光按亮度反推增益所以**不过曝**，
   逆光按对比度反推拉伸，常规按细节量反推锐化。

再配一句量化：`固定模式饱和率 26.7% → 自适应后 ≈X%（步骤 5 填）`。

## 七、步骤 3 的实测证据（2026-10-08，连续自适应最终验证通过）

这一节是答辩可直接引用的原始证据。数据来自一次 60 秒的连续自适应调度
（`stage08_auto_schedule/sched.log`），期间人手改变场景四次。

### 7.1 三条闭环都跑通了

| 环节 | 证据 |
|------|------|
| **感知** | 特征随场景真实变化：(90,47,38) → (6,0,23) → (111,69,37) → (4,0,10) → (96,54,34) |
| **决策** | MLP 判决 + 置信度门限；中间地带被正确拒绝（见 7.3） |
| **执行** | 60 秒共切换 **8 次**，另有 38 次被 `min_hold` 挡下；`PARAM` 连续跟随 |

### 7.2 PARAM 是"连续"的，不是切换时才动

同一模式内部 PARAM 也在变（这是"连续自适应"区别于"三档查表"的关键）：

| 时间 | 特征 | 模式 | PARAM | 说明 |
|------|------|------|-------|------|
| t=15s | (109,54,31) | 2 | **185** | 细节量 f3=31 → 锐化加强 |
| t=20s | (110,56,33) | 2 | **172** | f3=33 → 锐化收一点 |
| t=40s | (115,61,31) | 2 | **185** | f3=31 → 又加强 |

而跨模式时方向也全对：

| 场景 | 特征 | PARAM | 为什么对 |
|------|------|-------|---------|
| 强逆光 | contrast=84 | **255** | 反差最大 → 补偿最狠 |
| 逆光 | contrast=72 | **238** | 反差大 → 补得狠 |
| 全黑 | f1=5 | **255** | 亮度最低 → 增益拉满 ×1.99 |
| 常规·细节少 | f3=31 | **185** | 细节少 → 锐化强 |
| 常规·细节多 | f3=39 | **134** | 细节已多 → 锐化收着（避免放大噪声） |

### 7.3 置信度门限确实在挡"中间地带乱跳"

t=10s 那一行：

```text
心跳 t=10.0s MLP=1 模式=1：MLP_OUTPUT=0  特征=(41, 14, 25)  PARAM=178
```

MLP 说 0，但 MODE_SEL **保持 1 没切**。算一下：`(41,14,25)` 到类别 0（暗光）中心
的距离 = **33.8 > 25（门限）→ 拒绝**。

这就是为什么加门限：训练数据里 `f1` 只有 10 / 67 / 109 三个值，41 落在
**没有样本的中间地带**，MLP 在那里输出是随机的；门限让它"保持不动"而不是"跟着乱切"。

（对比：在更早一次未加门限的日志里，特征恒定 `(19,1,39)` 而 MLP 在 0/1 之间
来回跳，60 秒里切了 3 次还被挡下 6 次 —— 画面会明显闪。）

### 7.4 其它指标

| 项 | 实测 |
|----|------|
| 帧率 | 3571-1931 = 1640 帧 / 60.0 s ≈ **27.3 fps** |
| MLP 握手 | `MLP_START` == `MLP_DONE` 全程相等 |
