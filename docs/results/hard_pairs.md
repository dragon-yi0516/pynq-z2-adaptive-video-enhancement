# Hard pair 实测（2026-10-19）

数据：`data/hard_pairs.csv`，240 帧（4 个场景 × 60 帧）。
板子：stage13 rev02，`VERSION=0x0001020D`；权重与 bitstream 一致。
阈值：`u_lo=0.30`、`u_hi=0.55`（由本表标定）。

> 版本备注：早期一次 preflight 读到的是 stage12 的旧 overlay 文件
> （`0x0001030C`）；按采集时的 setup 输出，本文数据统一使用 stage13。
> 两版的 `PARAM`/四象限逻辑相同，stage13 只是多了 HDMI 分屏。

复现：

```bash
python3 tools/eval_spatial.py --csv data/hard_pairs.csv --u-hi 0.55 --u-lo 0.30
```

## 结论

**Pair 0 是主证据**：两个场景 `f_luma` 只差 1（9 vs 8），
MLP 都判 0，但四象限 `u` 从 0.101 变到 2.168，
空间决策把亮窗场景改判为 `mode 1`（60/60 帧），均匀暗场保持 `mode 0`。
这直接说明系统不是“只看全局亮度切三档”。

**Pair 1 是辅助证据**：`|Δf_luma|=16.2` 超出 10 的目标，
而且 MLP 已经用 `f_luma2`（49 vs 96）把两个场景分开了，
所以它不能单独证明“空间信息是唯一判据”。但它说明：

* 均匀正常光 `u=0.267` 被正确当成“均匀”，信任 MLP 的 mode 2；
* 正常亮度逆光 `u=1.151` 被正确改判为 mode 1；
* 在 0.30/0.55 阈值下，240 帧里 **0 次“保持”**。

如果时间允许，可以重采 pair 1：把均匀正常光调得更均匀（`u<0.30`），
并把逆光场景的 `f_luma` 压到 95~105，让 `|Δf_luma|<10`。
如果时间不够，报告里把 pair 1 标成“辅助”，主结论只引用 pair 0。
