# 吞吐与余量

## 理论吞吐

自定义 IP 是 1 pixel/clock，视频时钟 100 MHz：

```text
100 MHz × 1 pixel/clock = 100 Mpixel/s
```

## 实际负载

1280×720×29.76 fps：

```text
1280 × 720 × 29.76 ≈ 27.4 Mpixel/s
```

占 IP 理论吞吐约 **27.4%**，仍有约 **3.6 倍**余量。

## 720p60 的边界

720p60 约：

```text
1280 × 720 × 60 ≈ 55.3 Mpixel/s
```

仍在 1 PPC/100 MHz 的 100 Mpixel/s 以内，但会同时要求：

* OV5640 720p60 配置与像素时钟；
* HDMI/TMDS 720p60 时序；
* VDMA/DDR 带宽翻倍；
* 重新时序收敛与全部板上证据复测。

所以“IP 能否处理 60fps”和“整条采集/显示链能否稳定 60fps”是两件事。
当前版本选择 720p30，是为了保留时序/资源余量并把证据做完整；
720p60 属于后续工作，不是一周内应冒险改的部分。
