# 四象限空间决策：从“亮度分类器”到“亮度 + 空间布局”

## 1. 为什么需要它

当前 `data/features.csv` 的三类中心是：

| 类别 | f_luma | f_luma2 | f_grad |
|---|---|---|---|
| 暗光 | 9.7 | 0.2 | 17.2 |
| 逆光 | 66.4 | 44.6 | 21.4 |
| 常规 | 96.5 | 68.6 | 29.9 |

只用 `f_luma` 两级阈值就有 **98.5%** 准确率，`corr(f_luma, f_luma2)=0.997`。
也就是说，三类基本按亮度排开；三个全局特征无法区分：

* 整体偏亮的均匀场景；
* 中间暗、四周亮的逆光场景。

这两类场景的全局均值可能几乎一样，但需要完全不同的处理：
前者适合锐化/轻增强，后者适合压高光、提暗部。

## 2. 硬件已经有的信息

`stage12_adaptive` / `stage13_split` 的 `axis_video_proc` 已经统计了四象限：

| 寄存器 | 内容 |
|---|---|
| `0x38 QUAD_TL_TR` | `[31:16]` 右上、`[15:0]` 左上，单位 `sumY >> 16` |
| `0x3C QUAD_BL_BR` | `[31:16]` 右下、`[15:0]` 左下，单位 `sumY >> 16` |

软件侧 `AiVideoRegs.quads()` 返回 `(左上, 右上, 左下, 右下)`；
`spatial_unevenness()` 计算：

```
u = (max(q) - min(q)) / mean(q)
```

均匀照明 `u` 接近 0；窗口/侧光 `u` 明显大于 0。
实测样例：`quads=(534,304,532,298)` -> `u=0.566`；
`quads=(19,19,20,21)` -> `u≈0.10`。

## 3. 软件决策规则

`lib/adaptive.py` 新增 `decide_spatial(features, quads, mlp)`：

| 条件 | 决策 | 原因 |
|---|---|---|
| `u >= 0.55` | `mode=1`（逆光补偿） | 空间明显不均；即使 MLP 判 0，也不要用全局增益，避免亮窗打到 255 |
| `u <= 0.30` | 沿用 MLP 的 0/2 | 照明均匀，空间信息不提供额外证据 |
| `0.30 < u < 0.55` | `mode=None`，保持当前模式 | 边界不确定，宁可不动也不乱切 |

阈值按 2026-10-19 的 hard pair 实测取 0.30 / 0.55：

| 场景 | f_luma | u | MLP | 空间决策 |
|---|---|---|---|---|
| 均匀暗场 | 9.0 | 0.101 | 0 | 0 |
| 暗场+亮窗 | 8.0 | 2.168 | 0 | 1 |
| 均匀正常光 | 99.8 | 0.267 | 2 | 2 |
| 正常+逆光 | 116.0 | 1.151 | 1 | 1 |

均匀簇（0.10~0.27）和逆光簇（1.15~2.17）之间有很大的空档，
0.30/0.55 落在空档里，240 帧里 0 次“保持”。
**注意**：这是当前光源/摆法下的标定，换演示环境仍需复核。
`auto_schedule.py` 支持 `--u-hi` / `--u-lo` 覆盖，`--no-spatial` 可一键退回纯 MLP。

### 暗场保护

纯黑场景的四象限和值很小，比值会被噪声放大。`spatial_unevenness()`
在四块均值 `< 5` 时直接返回 0，让决策回到 MLP。

## 4. 数据格式

`data/features.csv` 前 4 列保持不变：

```
f_luma,f_luma2,f_grad,label
```

阶段 12+ 的采集会追加 5 列：

```
f_luma,f_luma2,f_grad,label,round,q_tl,q_tr,q_bl,q_br
```

* `round`：采集轮次（0/1/2），用于 leave-one-round-out；
* `q_*`：四象限 `sumY >> 16`。

旧的 4 列 CSV 仍然能被 `features_io.load_csv()` 读取；
训练/推理仍然只用前 3 个特征，模型和 bitstream 不需要改。

## 5. Hard pair 采集协议

目标：让 `f_luma` 接近，但 `u` 分开。

| pair | 场景 A | 场景 B | 目标 |
|---|---|---|---|
| 0 | 均匀暗场 + 灰卡 | 暗场 + 亮窗/灯 | `f_luma` 都 10–30，`u` 差 > 0.2 |
| 1 | 均匀正常光灰卡 | 正常亮度 + 窗口逆光 | `f_luma` 都 85–105，`u` 差 > 0.2 |

每个场景采 30–60 帧，保持手动曝光不变。推荐直接用：

```bash
python3 tools/collect_hard_pairs.py --per-scene 60 --wait 10
python3 tools/eval_spatial.py --csv data/hard_pairs.csv
```

`collect_hard_pairs.py` 会按场景提示、检查 `f_luma` 是否在目标带、
把四象限写进 `data/hard_pairs.csv`；`eval_spatial.py` 会打印：

* 每个场景的 `f_luma` / `u` 均值；
* MLP-only 的判决分布；
* 加四象限后的判决分布；
* 空间覆盖次数 / 空间保持次数。

## 6. 验收标准

一份能进报告的 hard-pair 结果应满足：

- 同一 pair 的两个场景 `|Δf_luma| < 10`；
- 同一 pair 的 `Δu > 0.2`；
- MLP-only 在两个场景给出相同（或相近）的类别；
- 加四象限后，逆光场景被改判为 `mode 1`，均匀场景保持 `mode 0/2`；
- `auto_schedule.py` 日志里出现 `空间覆盖：MLP=x -> 模式=1`。

如果 `u` 分不开，先检查：

1. 亮窗/灯是否真的落在某个象限里，而不是在画面正中央；
2. 四象限和值是否太小（暗场噪声底）；
3. 是否改了曝光/增益导致两个场景亮度不在同一带内。

如果仍然分不开，就如实写“四象限只有 4 块，无法定位小面积高光”，
不要为了结果好看硬调阈值。
