# 密闭演示盒 + 可控光源（材料清单与标定流程）

## 1. 这个盒子解决什么问题

现在的分类判据是三个硬件特征，而三个类别的**主要差别是画面亮度**：

| 类别 | 平均亮度 | 对比度(std) | 平均\|ΔY\| | 对应模式 |
|------|---------|-------------|-------------|---------|
| 0 暗光 | 11 | 13 | 1.8 | mode 0 暗光增强 ×1.5 |
| 1 逆光 | 77 | **74（最高）** | 2.1 | mode 1 逆光补偿 |
| 2 常规 | 124 | 22 | **2.5（最高）** | mode 2 细节锐化 |

（这三个物理量是从 `data/features.csv` 的类别均值和
`stage04_mlp_train/make_demo_csv.py` 里的换算公式反推出来的。）

现场演示有两个老问题：

1. **靠手遮镜头调不到合适的暗度**。默认自动曝光（`0x3503 = 0x00`）会在你调暗时
   自动拉长曝光补偿，画面亮度被顶回去 —— 实测遮镜头 `f_luma` 最低只到 27，
   而暗光类的中心是 10。中间那一段（"中等偏暗"）根本调不出来。
2. **场景落在训练没见过的中间地带时判决不稳**。训练数据每类只有 2~18 个不同取值
   （三个静止场景各拍 200 帧），所以特征一旦偏到 "f_luma = 30" 这种中间值，
   MLP 的输出就是任意的（实测 f_luma=30 被判成 1，而它离类别 0 的 10 更近）。

盒子 + 可控光源 + **手动曝光** 一次解决这两个问题：亮度完全由灯决定，
三档可以精确标定到原来的三个类别中心，判定稳定、演示可重复。

> **关键**：盒子必须配合手动曝光才有意义。见 `lib/exposure.py`。

## 2. 材料清单（约 100~200 元，淘宝都能买到）

### 必需

| # | 材料 | 规格建议 | 数量 | 作用 / 备注 |
|---|------|---------|------|------------|
| 1 | 遮光箱体 | 黑色哑光收纳箱，内尺寸 ≥ 25×20×20 cm；或密度板/亚克力自己粘 | 1 | 要塞得下摄像头 + 灯 + 目标卡片 |
| 2 | 黑色哑光内衬 | 黑色植绒布 / 黑色卡纸（**哑光**，别用亮面） | 若干 | 贴满内壁，消灭反射和杂散光 |
| 3 | 镜头密封材料 | 黑色海绵/泡棉 + 黑色电工胶带 | 1 套 | 镜头穿箱壁处**必须完全不漏光** |
| 4 | 主光源 | 白光 LED 灯板 + **恒流驱动器（带模拟调光/DIM 脚）** | 1 | ⚠️ 必须直流调光，见下面"不要买" |
| 5 | 调光旋钮 | 10 kΩ 电位器 / 0–10 V 调光器 / 可调直流电源 | 1 | 手动拧亮度，一拧就是一个场景 |
| 6 | 逆光光板 | 白光 LED 面板 + 亚克力匀光板（装在后壁） | 1 | 造 class 1：亮背景 + 暗主体 |
| 7 | 目标卡片 | 打印的网格/文字卡；黑色卡纸剪的剪影；纯白卡 | 各 1 | class 2 要**高纹理**；class 1 要**暗主体** |
| 8 | 柔光板 | 白色亚克力板 / 硫酸纸 | 1 | 压掉光斑，让照明均匀 |
| 9 | 12 V 电源 | 12 V 2 A 适配器 | 1 | 给 LED 驱动供电 |

### 可选（有则更好）

| # | 材料 | 作用 |
|---|------|------|
| 10 | 万用表 | 量 LED 电流，方便把三个档位**定量复现** |
| 11 | 定位标签贴 | 在电位器上标"暗 / 逆光 / 常规"三个刻度，演示时直接拧到刻度 |
| 12 | 遮光镜头盖 | 标定"全黑"档用 |

### ⚠️ 不要买 / 不要用

| 别用 | 原因 |
|------|------|
| RGB 彩色灯 | 颜色变化会通过自动白平衡影响亮度特征，还多引入一个变量 |
| 低频 PWM 调光器 / 手机屏调光 | 会和曝光、帧率打架产生**滚动条纹**，直接污染 `f_grad`（清晰度）特征 |
| 亮面内衬（白纸、铝箔、亮面塑料） | 反射杂光，"暗光"档永远暗不下来 |
| 大功率聚光灯直射 | 中心过曝、边缘暗，对比度失控，标定很难 |

### 用现成台灯代替灯板？先做三个测试

台灯**大概率可用**，但先花 5 分钟做三个测试：

| 测试 | 怎么测 | 不合格怎么办 |
|------|--------|-------------|
| ① 能不能连续调光 | 看是旋钮/无级触摸，还是只有开关 | 只有开关 → 中间档靠手动曝光凑 |
| ② 闪不闪 | 手机相机对着灯拍，看有没有横向滚动条纹 | 见下面「手机看闪 ≠ 相机出条纹」 |
| ③ 量程够不够 | 灯调到最暗，看 `f_luma` 能不能压到 ≈10 | 把灯放远，或灯前加硫酸纸 |

**手机看闪 ≠ 我们这个相机会出条纹。** 两者曝光时间差很多：
手机的曝光通常只有几毫秒；而这里的曝光是 736 行 ≈ **33 ms**，
足以把 100 Hz 的纹波平均掉（33 ms 覆盖 3 个多周期）。
所以先跑 `tools/box_calibration.ipynb` 里的「光源闪烁 / 条纹检测」那一格实测。

判据：行平均亮度曲线**平滑**、`f_grad` 连读 10 次极差 ≤2 → 光源没问题。
出现**规则周期起伏**才是真有 PWM 条纹。

真有条纹时的补救顺序（都不花钱）：

1. **把灯调暗 + 把曝光加大**（保持画面亮度不变）。
   条纹的可见程度取决于「曝光时间 ÷ PWM 周期」，曝光越长纹波越被平均掉。
   注意方向是「灯暗 + 曝光长」，不是「灯亮 + 曝光短」。
   曝光上限约 736 行（受 VTS 限制），所以这一招最多再给你 1.4 倍余量。
2. 还不行 → 说明灯的 PWM 频率太低。在灯前加硫酸纸/中性灰片减光，
   腾出曝光余量，再重复第 1 步。
3. 还不行 → 换灯（LED 灯带 + 直流调光模块，约 30 元）。

> 进阶（**能拆开台灯才行**）：在 LED 两端并一个 1000 µF / 16 V 电解电容，
> 把 PWM 电流纹波平滑掉。密封的台灯一般够不到驱动输出。

## 3. 装配要点

```
        ┌──────────── 箱体（内壁全黑哑光）────────────┐
        │                                            │
        │   [逆光光板]         ← 后壁，造 class 1     │
        │        │                                   │
        │        │  [目标卡片/剪影]                   │
        │        │        │                          │
        │        │        │      [主光源 + 柔光板]   │
        │        │        │            │             │
        │        └────────┴────────────┘             │
        │                     │                      │
        └─────────────────────┼──────────────────────┘
                              │  ← 镜头孔（海绵+胶带密封）
                        [OV5640 摄像头]
```

1. **先把内壁贴黑**，再装灯和摄像头。
2. **镜头孔一定要密封**。这一步不做，暗光档就只能到 `f_luma ≈ 27`
   （漏光进来的那点亮度正好够 AEC 用）。
3. **主光源加柔光板**，别直射镜头。
4. **逆光光板装在后壁**，前面放黑色剪影 —— 逆光类的判据是**对比度高**，
   不是"整体亮"。
5. 灯和摄像头的相对位置**固定死**（热熔胶/螺丝），标定完不许再动。

## 4. 三档场景怎么造

| 档位 | 目标 f=(luma, luma2, grad) | 灯怎么调 | 目标物 |
|------|---------------------------|---------|--------|
| **暗光** | (9.7, 0.2, 17.2) ± (4.0, 0.4, 4.1) | 主光源关到最暗（或全关） | 随便 |
| **逆光** | (66.4, 44.6, 21.4) ± (9.5, 7.0, 1.7) | 后壁光板开、主光源关 | 哑光黑色的遮挡物（黑卡纸/黑绒布/哑光黑塑料板） |
| **常规** | (96.5, 68.6, 29.9) ± (9.5, 6.2, 1.0) | 主光源开到中亮 | 打印的网格/文字卡 |

（这是 2026-10-13 重采 540 帧后的实测中心，也是 `lib/adaptive.py` 实际在读的那份。
同一组数字在 `tools/box_calibration.ipynb` 里**现算**，调灯时盯着那个 notebook 的 `observe()` 输出。）

要点：

* 三档两两距离：0↔1 = 72.2、0↔2 = 111.2、**1↔2 = 39.4**（最近的一对是逆光和常规）。
  调灯时**距离 <20 才算命中**，否则特征落在训练分布边缘、判决不可信 ——
  实测 2026-10-15：距离 32/21/47 那次 MLP 三档**都判对了**，但那是外推碰巧对，
  `step5_compare.py` 照样会把这几行标成"不要进报告"。**别拿"MLP 判对了"当达标判据。**
* **逆光档要造"明暗并存"的画面**：剪影卡 + 光板同时进画面，`luma2` 才会上去
  （实测 class 1 的相对对比度 std/mean ≈ 1.1，比 class 2 的 0.8 高）。
  只把灯调暗是**变不成逆光的** —— 那只会往暗光类靠。
* **逆光档的遮挡物：任何哑光黑色的东西都行，不必剪成人形** —— 特征看的是统计量，不是形状。
  只要满足三条：① 黑物占画面约 1/3~1/2，四周露出**亮的光板**（`f_luma2` 靠这个）；
  ② 表面平整、**没有字迹/图案/褶皱**（否则 `f_grad` 冲过 25 就会被判成常规档）；
  ③ **哑光不反光**（亮面黑塑料、黑手机屏、黑胶带会在灯下反出高光点，同时污染 luma2 和 grad）。
  实测（2026-10-15）：光板不够亮时 `f_luma2` 只有 22（目标 44.6），距离 26 → 被判"摆位没到位"。
* **常规档的 `f_grad` 最高**，所以必须**有纹理**，对着白墙不行。
* "逆光 vs 常规到底是靠亮度还是靠对比度分开的"，答辩前建议按第 8 节那个实验实测一次，
  别想当然。

## 5. 标定流程

用 `tools/box_calibration.ipynb`（新加的），按格子顺序跑：

1. **第 1 格**：初始化 + 自动切到手动曝光；
2. **第 2 格**：实时看 `f=(f1,f2,f3)` 和到三类中心的距离 —— 拧灯的时候盯着它；
3. **第 3 格**：扫曝光 / 增益，先挑一个合适的固定工作点
   （原则：常规档的目标物在"主光源中亮"时 `f_luma ≈ 109`）；
4. **第 4 格**：三档各记录一次读数，自动判断是否命中目标；
5. **第 5 格**：三档各抓一帧并排看，确认画面差异肉眼可见；
6. **第 6 格**：收尾（恢复自动曝光 + 释放资源）。

**标定成功的意义**：因为目标就是原来的三个类别中心，
**现有模型和阶段 7 的 bitstream 直接可用，不用重训、不用重出 bit**。

> 如果怎么调都命中不了那三个点，才需要重采数据重训
> （阶段 4 → 5 → 6 → 7，约 1.5~2 小时）。

## 7. 常见坑

| 现象 | 原因 / 处理 |
|------|------------|
| 调暗了但 `f_luma` 不动 | 没切手动曝光。先跑 `exposure.set_manual(iic)` |
| 暗光档最低只能到 27 左右 | 镜头孔漏光。补密封海绵/胶带 |
| 画面上有滚动条纹 | 灯是低频 PWM 调光。换直流调光，或把 PWM 提到 ≥20 kHz |
| `f_grad` 一直很低（<20） | 目标物太平（白墙）。换成打印网格/文字卡 |
| 逆光档判成 2 | 对比度不够。后壁光板开大些，或剪影换成纯黑卡纸 |
| 三档读数每次都不一样 | 灯或摄像头位置动过。固定死再重新标定 |

## 8. 一个可以提前准备的答辩问题

评委可能会问：**"这是不是就是个亮度分类器？"**

从数据看，诚实地说 `f_luma` 确实是主判据（三档 10 / 67 / 109 分得很开）。
但 `f_luma2`（对比度）在逆光类上有明显区分 —— class 1 的对比度 74，
而比它更亮的 class 2 只有 22。

**建议在盒子里做个实验来验证**：把灯固定到 `f_luma ≈ 77`
（正好落在 class 1 和 class 2 之间），然后换不同对比度的卡片，
看 MLP 会不会在 1 和 2 之间翻转。

* 会翻 → 你有"不是纯亮度阈值"的硬证据，可以直接演示；
* 不会翻 → 说明确实偏亮度判据，答辩话术就要相应调整
  （说"主判据是亮度，对比度辅助区分逆光"），别被问住。

这一条**需要实测**，不能想当然。

## 9. 2026-10-13 复测：当前三档中心与锁定工作点

重采一轮数据并重训后（540 帧、`check_features` 0 FAIL），盒子三档的实测中心变成：

| 档位 | f_luma | f_luma2 | f_grad | 约亮度 |
|------|--------|---------|--------|--------|
| 暗光 | 9.7 ± 4.0 | 0.2 | 17.2 | 11 |
| 逆光 | 66.4 ± 9.5 | 44.6 | 21.4 | 75.5 |
| 常规 | 96.5 ± 9.5 | 68.6 | 29.9 | 109.7 |

（第一版是 10 / 67 / 109，差别主要在常规档略暗一点。**以你手上这一刻的实际测量为准**，
把上面的数覆盖掉即可。）

**锁定工作点 = 736 行 + 增益 0x20**（常规档 luma ≈ 122，目标 124）。
这个值现在集中放在 `lib/exposure.py` 的 `WORKPOINT` 里 ——
`tools/collect_dataset.py`、`tools/step5_compare.py` 和三个演示/验证 notebook 都引用它，
改一处就全局生效。重新标定后记得同步更新这张表。

> ⚠️ **采集、演示、对比实验必须用同一档**。这是 2026-10-13 实测踩出来的：
> 演示时用自动曝光，AEC/AGC 一改曝光/增益，噪声就让 `f_grad` 整体高了十几个点，
> 常规档读成 `(109,57,36)`（训练中心 `(96.5,68.6,29.9)`），**逆光档一次都判不出来**。
> 现在的演示/验证 notebook 都会自己锁这一档（初始化格里 `USE_MANUAL_EXPOSURE = True`）。

**步骤 5 的对比实验**（固定强度 vs 连续自适应）在 **Jupyter 的一格里跑**：

```python
import sys; sys.path.insert(0, "/home/xilinx/jupyter_notebooks/ai_video_2024.2")
import tools.step5_compare as s5
s5.main(["--wait", "10", "--shots", "3"])
```

它自动用这档工作点，把四个指标（均值 / std / 水平差分 / 饱和率）写成
`data/step5_compare.csv`，并直接打印"报告里建议这么写"的句子。

> **为什么要"进内核"跑**：脚本要下载 bitstream、起 VDMA、写 I2C 配摄像头 ——
> 也就是要**独占 PL**。PYNQ 的 PL 同一时刻只能有一个主人，所以
> ① 这一格跑完之前别在同一个内核里跑别的 overlay 格（05/06/07/13 都会 `bring_up()`）；
> ② 想再跑一遍就**再运行一次这一格**（脚本复用本进程已加载的 overlay，不重新下载 bitstream），
> 不要改成 `subprocess.run(...)` —— 那样内核和子进程会抢同一块 PL，实测直接 SIGSEGV
> （Python 侧只看到 `returncode=-11`，很像"跑不了第二次"）。
> SSH 终端里也不要跑：不加 `sudo` 会缺 root 权限，加了 `sudo` 又会因为 XRT 环境被清空而 `No Devices Found`。
