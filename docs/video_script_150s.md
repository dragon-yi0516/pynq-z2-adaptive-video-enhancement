# 2 分 30 秒比赛演示视频脚本

## 1. 拍摄前准备

- 板上 overlay 必须是 stage13，`VERSION = 0x0001020D`；
- 只用一套 Jupyter kernel，关闭其他 Notebook；
- 运行 `python3 tools/check_weight_sync.py`，确认权重、HLS 源码和 bitstream 对应；
- 使用手动曝光，暗光、逆光、正常光之间不重新自动曝光；
- HDMI 显示器亮度约 70%，避免灯光反射；
- 手机横屏固定在三脚架上，关闭 HDR、美颜、人像模式和数码变焦；
- 建议 1080p 60 fps 或 4K 30 fps，快门约 1/50 s，白平衡固定在 5000～5600 K。

分屏镜头使用 `stage13_split/13_verify_split.ipynb`。全屏直通和处理对比使用 `tools/ab_toggle.ipynb`。

分屏是“左侧原始画面的前 640 列 + 右侧同一段列的处理结果”。拍摄分屏时，把主体完整放在摄像头画面的左半边；否则主体会在两半屏幕里被截断。

## 3. 完整中文口播

> 大家好，这是我在 PYNQ-Z2 上完成的 OV5640 场景自适应视频增强系统。板内运行的是 stage13，版本寄存器为 `0x0001020D`。
>
> 普通摄像头的自动曝光主要按整幅画面调整亮度。遇到窗边逆光时，提亮全局会让窗户更亮，压暗高光又会让主体变黑。所以我没有只做一套固定滤镜，而是让 FPGA 先统计场景，再决定处理方式和强度。
>
> 整条链路是 OV5640 采集、去马赛克、自研 AXI4-Stream 处理 IP、VDMA 缓存，最后送到 HDMI。PL 每个像素统计亮度、亮度平方、梯度和四象限亮度；PS 用 3-8-3 定点 MLP 和空间规则做判断，模式在帧首锁存，参数连续变化，所以切换时画面不会撕裂。
>
> 先看暗光场景。这里保持固定曝光，不依赖摄像头自动增益。画面从偏暗逐渐提亮，PARAM 不是简单地切三档，而是按当前特征连续调节强度。
>
> 接下来是逆光场景。屏幕左边是原始画面，右边是处理结果，两边对应同一个 640 列源区域，可以直接比较。均匀暗场和暗窗场景的亮度指标只差 1，MLP 都判成暗光；加入四象限后，亮窗场景被改判为逆光补偿。这说明系统不是只按亮度做普通分类。
>
> 正常光下，处理重点是保持整体亮度并增强纹理，所以这里切到锐化模式。文字边缘和织物细节会更清楚。
>
> 在自动运行中，四个场景的最终模式是 0、1、2、1。固件里还有置信度门限和驻留时间，避免边界画面来回跳。整个工程同时保留了 HLS CSim、真实场景、hard pair、1 小时运行和 Vivado 实现报告。
>
> 在 720p30 下平均约 29.76 帧每秒，一小时内记录 107,137 帧；用户已指定约束内的时序检查通过，WNS 为 `+0.120 ns`。完整源码、数据、报告和四个可复用 Skill 已经开源在 GitHub。

## 4. 三个场景怎么摆

### 暗光

- 主灯调低，保留一个轮廓清楚的物体；
- 不要直接把镜头完全遮黑；
- 保持手动曝光，先录直通，再切自适应，每种状态停留至少 3 秒；
- 屏幕里应同时看到暗部层次和提亮后的结果。

### 逆光

- 窗、台灯或亮屏在画面中偏亮，但不要让整幅画面过曝；
- 主体放在摄像头画面的左半边，确保分屏时左右显示同一区域；
- 先录 3 秒分屏，再从侧后方拍手机、板卡和显示器同框；
- 近景再补 5 秒，让观众看清原图与处理后。

### 正常光和锐化

- 使用印有文字的纸、棋盘格、包装盒或织物；
- 不要用纯白墙展示锐化；
- 先用直通，再切到 mode 2 和较高 PARAM，保持构图不变。

## 5. 推荐拍摄顺序

1. 录整机全景和接线，约 20 秒；
2. 录 `VERSION`、IP 清单和权重检查，约 20 秒；
3. 暗场录直通、A/B 和近景，各 8～10 秒；
4. 逆光录分屏全景和近景，各 8～10 秒；
5. 正常光录直通、锐化近景，各 8～10 秒；
6. 录自动调度日志和四场景切换，约 20 秒；
7. 录 GitHub 页面和最终整机画面，约 10 秒；
8. 所有素材保留前后 2 秒，方便剪辑。
