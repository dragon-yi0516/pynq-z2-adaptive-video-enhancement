## 必须满足（缺一不可）

- 训练集准确率 **> 85%**（真机三类场景拉得开的话，一般能到 95%+）。
- 混淆矩阵对角线明显占优（说明三类没混在一起）。
- `量化前后一致率 > 97%`。
- `溢出检查 int32_ok = True`、`w1_sat = 0`。
- `weights/mlp_weights.h` 生成，且 `from_c_header()` 能原样读回。

## 为什么不用 sklearn

见 `mlp_common.py` 顶部注释，三条：板子不一定装、要把归一化折进第一层、PC 零依赖可单测。
如果你确实想用 sklearn 对比一下，可以把 `03_mlp_train.ipynb` 里
`mc.train(...)` 换成 `MLPClassifier`，但**量化与导出仍然必须走 `mlp_common.py`**，
否则训练与推理的定点约定会不一致。

## 为什么要做溢出检查

定点推理里有三处乘法累加：

```
z1 = b1 + Σ (x_q * w1) >> 8      (3 项)
y  = b2 + Σ (h  * w2) >> 8      (8 项)
```

如果只用“典型输入”心算，很容易漏掉最坏情况。`quantize()` 会用训练集里
每个特征的最大值算出上界，确认两层都不会超过 int32，并检查 w1 有没有量化饱和。
这一步不过，硬件上就会出现“笔记本里对、板子上错”的现象。

## 常见失败与处理

| 现象 | 原因 | 处理 |
|------|------|------|
| 准确率 < 85% | 阶段 3 三类场景没拉开 | 回阶段 3 重采，遮镜头要遮严、逆光要真的对着光源 |
| 一致率 < 97% | 特征量级过大导致量化精度不够 | 调小 `mlp_common.INPUT_SHIFT`（例如 5），或增大训练样本 |
| `w1_sat > 0` | 某个特征的标准差太小（数据几乎不变） | 检查该特征是否一直是常数（多半是硬件没统计到） |
| `int32_ok = False` | 权重过大 | 降低 `INPUT_SHIFT` 重训 |
